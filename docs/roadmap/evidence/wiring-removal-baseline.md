# Behaviour to carry across Wiring removal

The current compiler was exercised on 26 November 2026 with `moth tests --tag wiring --terse`. All 102 registered target expectations passed: 97 HTML expectations (27 successes and 70 rejections) and five additional HTML-Wasm expectations (two successes and three rejections). This records the behaviour before retirement. The fixtures, diagnostics and exact output remain available in the [tested tree](https://github.com/nyejames/moth/tree/a6d40d7d3e07f49756fadf6ad2034772b48eebc9/tests/cases). Refresh this evidence at removal if affected code or fixtures have changed.

| Witness in the tested tree | Disposition |
|---|---|
| `wiring_wire_runtime` | Preserve the dual-target read/forward result for the later scoped getter. Both targets produced `wire read=initial forward=initial mutable=after number=7 loop=ab`. The immutable binding is read directly and through forwarding. The mutable binding is reassigned before its only forwarded read. Loop iterations have distinct bindings. |
| `wiring_route_arrow_and_return_arrow` and `wiring_route_capture_error_runtime` | Payload preparation ran once at formation in written order, even when the consumer ignored the Route. The former observed `order_effect=beforecapture-1capture-2after`. The latter produced `route received failed`. For equivalent closure behaviour, evaluate fallible or side-effecting inputs before forming the closure. Work intentionally placed in its body runs zero, one or several times at invocation. |
| `wiring_route_input_only_imported_success`, `wiring_route_input_private_export_rejected` and `wiring_private_trait_route_input_sidecar_success` | Retain the publication questions. A signature-only nominal must be reachable across an import, an illegal private export must be diagnosed, and a generated helper must retain its provider-owned dependency. Express ordinary coverage at retirement where applicable and callback-only coverage when closures land. |
| `wiring_route_partial_outside_rejected` | The source constructs an ordinary choice with a missing field. Move the case to ordinary constructor coverage during removal and retain `invalid_call_shape.missing_argument`. |
| `wiring_route_wasm_rejected`, `wiring_route_wasm_generated_rejected` and `wiring_route_wasm_unreachable_accepted` | Retire the Route-specific target check. Preserve the requirement that reachable unsupported operations get a target diagnostic, generated code participates and dead code adds no target demand. Use supported ordinary target tests during the gap. |
| `src/builder/tests/host_requirements_tests.rs` | The old host cases distinguish language validity from an unsupported ABI. After removal, keep independent host-ABI coverage using a still-legal Moth type that the ABI rejects. Add callback-specific host rejection when callback declarations are legal. |

At the implementation checkpoint, reconcile the full `wiring_*` manifest inventory, Rust-hosted source and changed neighbouring tests against these dispositions. Mark an old case as retired, moved to a surviving owner, or represented by a future closure witness. Record exact case IDs, backend verdicts and any new observation here when the table alone would lose coverage. The old restrictions on argument origin, partial constructors and reserved names are intentionally retired. Package export routes, URL routes and ordinary argument routing keep their own coverage.
