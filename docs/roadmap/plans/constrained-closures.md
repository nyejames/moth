## Delivery contract

Give a Moth library one way to accept caller-supplied behaviour. A synchronous helper can borrow a callback. A component can keep a handler under an explicit owner. Deliver the former Wire reader and constructor Route use cases through that surface, then maintain only the closure path. This is a language and compiler change across separately compiled Moth modules. Implementing a browser event system, automatic redraw or a Channels runtime is separate work.

Read the permanent [callback reference](../../docs/functions/parameters-and-defaults.mtf), [surface syntax](../../moth-surface-syntax-design.md#parameter-brackets), [Channels contract](../../docs/async/channels.mtf), [runtime access and lifetime authorities](../../developer-docs/memory-management/overview.mtf) and the current [Wiring contract](../../docs/wiring/wiring.mtf) before activation. The [compiler](../../compiler-design-overview.md) and [build](../../build-system-design.md) authorities own stage boundaries. Follow [AGENTS.md](../../../AGENTS.md) for the routed data-layout, testing, validation and review rules. The progress matrices distinguish design from working features.

### Source and library contracts

- A callback signature uses the named function parameter form, such as `label |row Row| -> String`. Use the same exact value types, access modes and conventions for signature parameter names. Its contextual literal uses names only, such as `|item| => item.title`. The empty form is `|| => expr`. Parse the inner parameter brackets and return arrow at their own depth. Keep existing loop, option and catch binders and trait receivers intact. Changing the name inside a literal cannot change the library signature.
- The immediate callback receiver supplies the parameter types. Each invocation receives the declared arguments and can produce zero or one ordinary success result. Omit the return arrow for zero. The single expression has return-like receiving context, including numeric literals, choice construction and a value returned by a named helper. A no-result call can supply a no-result callback. Reject statement bodies, extra success slots, explicit callback error slots, loss of the expected parameter types and unanchored literals. No general function type, callable trait, partial application, bare callback return, const closure or closure factory is needed.
- Collect lexical captures from resolved body uses, distinguishing incoming parameters, constants and named functions from enclosing runtime places. Ordinary reads grant shared access. An external write requires ordinary explicit `~` at its use, for example `|| => increment(~count)`. Use existing place and alias checks. Reject conflicts with other arguments, captures and live aliases, including two syntactically different paths to the same child. Every callback may run repeatedly or never. It cannot consume an environment member on the assumption it will run only once. Capture formation does not run body expressions. User-written precomputation and `copy` before formation preserve eager work and independent data when required.
- Every invocation must be provably non-suspending, including transitive calls, generated bodies, imported calls and implicit child joins. Use the Channels meaning of `$no_suspend` without requiring an annotation on every helper. A wrapper calling an opaque callback can rely on this guarantee without specializing for each literal. An opaque callback parameter in this system already guarantees non-suspension. Unknown foreign effects do not. A callback can still fail, mutate permitted state or take a long time. The containing library function can wait between completed invocations. A capture loan still held by that function remains live across the wait.
- Treat an opaque invocation as capable of implicit built-in failure. Reuse checked numeric failure, local recovery, private propagation and the exported invoker's boundary. If a handler fails after registration, its invoker receives the failure. A `catch` around installation only covers work performed in that call. A proven local simplification can remove an unreachable failure edge without weakening the public contract. Preserve traps and explicit error channels on ordinary helper calls. A helper with a custom error can recover inside the expression or in a named wrapper using ordinary language rules.
- A plain parameter can invoke, ignore or forward the callback for the dynamic extent of the call. To retain it, declare `into this`, `into owner` for a writable owner parameter or `into return` for the single returned owner. Resolve the destination to a receiver, formal parameter position or success position. Validate each store and forwarding path against that declaration, including indirect storage inside an aggregate. A declaration permits retention and may be unused on some paths. A successfully formed environment can retain only permitted, sufficiently long-lived shared data. A copied capture must itself have valid placement. Last-use optimisation cannot manufacture an outlives proof.
- Named Moth struct fields provide concrete storage. A field declares the signature, a constructor receives its handler for the constructed owner, and a setter uses ordinary writable field access. An installed field can be invoked or lent to a plain slot. A retaining wrapper can forward an incoming callback to the same proven destination. It cannot extract a field into an independently retained handler. Lend mutable model state at each invocation or return a message. For V1 treat a stored callback as non-copyable under the ordinary recursive `copy` check. Aliasing or returning its owner under normal lifetime rules is a separate operation. Represent optional installation using an ordinary optional component or holder with a required callback field. A callback returning an option such as `|| -> String?` still occupies its field.
- A result can borrow from invocation arguments, captures or values they retain. An opaque signature gives the consumer a conservative union of those sources. Accept a result when all applicable sources outlive its use. Admit immediate drawing of a borrowed title. Reject a result or nested retained edge escaping a shorter source. An independent copy made while the source is valid or existing proven region placement can resolve the case. Add no closure-specific lifetime notation, unbounded flow search or implicit clone. The restricted host ABI and independent channel messages do not acquire permission to carry Moth callbacks.

## Phase 1. Make call effects trustworthy across modules

- [ ] Start with existing ordinary calls. Trace `PublicCallSummary`, its signature-only seed, HIR failure verification and `module_compilation/generated/{convergence,constraint_convergence}.rs` under `src/compiler_frontend/`. Reuse the existing producer of settled failure facts and public summary projection. Keep built-in failure, explicit errors, traps, fast semantics and suspension distinct. Under the [callable constraint rules](../../docs/directives/constraints.mtf), an opaque handler can trap or use fast arithmetic. Catching a recoverable error cannot by itself prove the invoker infallible or safe-math. Try a wrapper with each constraint and a control that only registers the handler.
- [ ] Consume the Channels suspension proof if available. Otherwise deliver the shared, conservative proof needed here with an actual named-call consumer. Positive evidence must cover all reachable direct and transitive targets, including joins. Unknown or incomplete evidence cannot certify a closure. Evaluate recursive calls using the existing component/convergence machinery where applicable. A cycle initialized to a default must never certify an unexamined foreign edge. This step does not require a scheduler. Recheck the producer when scheduling operations become executable.
- [ ] Extend stable declaration and concrete call records where the current owners require it. `public_interface/model.rs` separates `PublicParameterContract` from completed `ConcreteCallSummaryRecord`. Project signatures using canonical types and parameter positions. Validate completed effects before consumer publication. Exercise direct import, re-export and generic specialization, including a provider-only helper changing from non-suspending to possibly suspending. Check that completed public interface equality and a fresh consumer reflect the change. Exercise warm-cache invalidation only where semantic reuse exists at activation.
- **Phase audit.** Compare local, imported and generated results. Check stale or missing summaries, failure caught in a wrapper, unknown foreign effects and inactive code. Audit for a duplicate effects pass or second summary that could diverge. Commit this phase independently only with a real consumer exercising its new facts.

## Phase 2. Prove the lifetime of arguments, captures and results

- [ ] Under `src/compiler_frontend/`, trace the actual `analysis/borrow_checker/` call transfer, place overlap and return-alias owners and the post-borrow topology handoff. `FunctionReturnAliasSummary::Fresh` excludes parameter-root aliases in that summary. It cannot prove independent results, fresh captured storage or absence of nested edges. Have the implementing agent demonstrate which mandatory proofs the current revision supplies.
- [ ] Use existing accepted ordinary access, return and aggregate-store cases to establish scoped loans and retained-edge validation at the owning stages. Record the capture's source place and access locally. Publish only information a consumer can interpret, such as a formal source position, retention destination and conservative result dependencies. No provider-local place, region, HIR or allocation ID crosses the boundary. Use the bounded conservative rule for opaque callbacks even when a caller cannot inspect the body.
- [ ] Test a borrowed field read immediately, the same result saved past its source, an owner with a nested shorter borrow, two paths to a shared child and an independent copy. Check replacement while the old result remains borrowed. Validate success, recovery and early exit. Where future explicit regions permit placement, compare proven longer-lived storage with a genuinely dangling edge. Missing mandatory evidence blocks the affected behaviour on every target. Keep optional transfer optimisation independent.
- **Phase audit.** Trace each proof to its consumer. Attempt an indirect escape through a helper, returned aggregate or owner replacement. Check that the production checker remains bounded and program legality matches across profiles. Reuse the reference/operational oracle for cases within its model. Document any limit without treating an out-of-model case as a passing proof.

## Phase 3. Switch the public surface once

Prepare these units separately and integrate them as one tested source change. Keep the normal Wiring behaviour available through phases 0-2. If earlier proof work has no ordinary consumer, land it here with its first real use. Publish a checkpoint only when the source, borrow checker and advertised targets agree.

1. **Declare and resolve.** In `declaration_syntax/type_syntax/parse.rs`, `declaration_syntax/signature_members.rs`, `ast/statements/functions.rs` and `ast/expressions/call_arguments.rs`, extend the signature member and immediate receiver owners. Parse nested callback signatures, `into` destinations and contextual literals there. Check arity, access, output and no-shadowing before body lowering. Resolve closure-local and outer names by identity once. Preserve ordinary argument evaluation order, named argument routing, choice defaults and normal inference. Test empty inner brackets, a callback in the middle of an outer list, a mutable input, an omitted output and a callback in a trait requirement with the normal receiver. Compare slot contracts during conformance, import and specialization. Keep closure signature members restricted to ordinary invocation inputs.
2. **Form and invoke.** In the existing typed expression and HIR owners, represent closure formation separately from invocation through a parameter or field. The existing `CallTarget` in `external_packages/ids.rs` describes direct targets. `HirExpressionKind::RouteConstruct` builds choice data. Neither supplies invocation semantics. Reuse ordinary function body lowering and checked call continuations. An environment records its resolved captures once. Keep code origins and call sites distinct and make empty environments cheap. Validate arity, types, captures, result and failure edges, reachability and source spans in HIR before analysis. Avoid generic adapter functions per call or a whole-program search over possible closure bodies.
3. **Verify forwarding and storage.** At the provider, check that a plain slot never escapes, including through another retained parameter or a struct constructor. For a retained slot, verify the actual owner on every retaining path. At the caller, verify capture access, lifetime and destination against the published signature. A factory may forward into the one owner it returns. A setter may invoke, skip or replace its handler. Account for committed stores on failure as ordinary Moth side effects. Never infer that catching an error undoes an earlier installation. Check that rejection and successful cleanup are independent of GC.
4. **Lower only validated operations.** Implement the scoped invocation and owner-field operations for HTML-JS through the existing HIR backend. Use explicit captured storage and ordinary Moth error delivery. Preserve per-iteration binding instances. For HTML-Wasm, execute the existing read/forward workloads through the replacement surface. Where another closure feature needs an unavailable physical capability, reject reachable uses in `src/backends/backend_feature_validation.rs` before lowering, including generic bodies. Exercise a caller-defined closure whose body alone references a private helper or package binding and is invoked by an imported provider. Verify that HIR reachability and module linking retain executable targets without charging their effects to formation. Test removal of unreachable demand. Use existing target partition, not a source-level switch. Moth-owned component invocation suffices for the retained example.
5. **Remove the superseded language.** Remove the Wire/Route parameter kinds, special `of` grammar, contextual partial-choice parser, name reservations specific to these heads, public projections, Route HIR node, target flag, diagnostics and dead tests. Search types and symbols, including `parse_route_capture_arguments`, `wire_argument_origin_is_eligible`, `RouteConstruct` and `validate_wasm_constructor_routes`. Separately check const eligibility, TIR walks, reachability, HIR validation/remapping, generic materialisation, JS and Wasm. Preserve choice constructors/defaults and package, export and URL routes. Use ordinary new-grammar diagnostics for old spellings. Rewrite public docs, site navigation, compiler/build/memory references and dependent package notes. Update progress only to the support actually verified.

**Phase audit.** Run the acceptance cases below from the normal CLI. Inspect capture acquisition, callback failure delivery, proof transport and release on each exit. Audit dead branches and duplicate metadata against the Phase 0 inventory. Review changed diagnostics for useful source spans and both sides of an incompatible contract. Exercise the documented examples with the supported targets before publishing this cutover.

## Acceptance cases for the cutover

| Case | Required observation |
|---|---|
| Scoped row label | Format `"Save"` with an outer `"Action: "` and produce exactly `"Action: Save"`. A getter reading `row.title` can feed a synchronous painter without copying. An explicit second read after legally updating the model sees the new title. A live shared capture cannot serve as a mutable observer across a conflicting write. |
| Old Route timing | Hoist a fallible or side-effecting constructor argument to preserve formation-time evaluation. Compare with the expression inside the closure at zero, one and two invocations. Check exact count, order, error handler and absence of work after failure. |
| Scoped edits | A plain repeated callback calling `increment(~count)` changes the counter twice. Reject a missing write marker, an overlapping exclusive argument and any path storing the borrowed callback. A retained handler instead taking a model as an exclusive invocation parameter can change that model twice. |
| Component events | Register a read-only ID and a `String` event input in a Moth-owned row. Invoke the retained field twice and assert both precise choice payloads. Check forwarding through an imported wrapper, conditional installation, replacement and teardown. Each retained edge ends when its owner and any live result borrows permit it. Count obligations where the representation has them. Repeated rows use distinct captured IDs. |
| Retention and escape | Accept `into this`, a named writable owner and `into return` with sufficient lifetime proof, including an independently prepared snapshot. Reject an undeclared or different destination, a retained exclusive capture, an extracted field installed into another owner and a result outliving one possible capture. Check a nested dangling case even when the outer result root is fresh. |
| Failure and suspension | Checked overflow occurs at invocation. A registration-only call never runs the body. A private wrapper may propagate built-in failure and an exported wrapper must recover or declare its boundary. Reject a callback that directly or transitively waits, including an implicit join or unknown foreign effect. Accept a verified unannotated helper. When Channels is executable, run an event loop that waits between completed invocations and validate live loans across the wait. |
| Public contracts and targets | Repeat positive and negative checks across two modules, an alias/re-export and a generic instance. Vary a retention destination and a callee effect without changing its ordinary value signature. Prove the freshly compiled consumer observes the changed contract. Check invalidation where reuse is implemented. Exercise HTML-JS, supported HTML-Wasm read/forward cases, reachable unsupported uses and dead unsupported uses. |

- **Phase audit.** Check the full path from a public callback slot to its last invocation, result use and cleanup. Verify the explicit UI examples, live references, stale Wiring links, survivor searches and target matrix. Close or assign any independently scoped UI runtime work to its actual owner. Delete this plan and its roadmap entry in the commit that completes it, leaving the durable contracts and tests in place.

## Audit closeout for every phase

Map the phase to concrete areas in the [audit guide](../audit-guide.md). Run a correctness audit and a redundancy audit of the touched owners at every phase. At the source cutover and final integration, also cover tests, diagnostics, documentation, style, comments and performance across the areas each touches. A formal run covers one kind and one area. Correctness findings use the bug queue and coverage log. Reserve report IDs for the other kinds before inspection and use the open/closed indices. Mark existing coverage stale when implementation changes invalidate it.

Use independent review for capture legality, lifetime proof and provider/consumer agreement. Record evidence, repair verified findings in separate implementation tasks and have a different reviewer repeat the failing witness or inspect the invariant. Re-audit fixes where evidence changed. Each phase ends with its named audit, relevant tests, zero unresolved correctness or redundancy findings in its scope and the separate [Slice review](../../../AGENTS.md). Check deletion, ownership, diagnostics and meaningful test coverage before advancing.
