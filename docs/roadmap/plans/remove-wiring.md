# Remove Wire and Route parameter contracts

| Status | Current slice | Blockers | Next action |

## Contract

Remove the two compiler-owned parameter heads before the surface syntax migration. The intervening grammar has ordinary Moth functions, choices and constructors. Scoped callbacks and retained closures arrive after that migration. No compatibility switch, migration diagnostic, temporary replacement or closure implementation belongs in this change. Leave the existing const/access work and the source grammar for other features intact.

Use [AGENTS.md](../../../AGENTS.md), the [compiler authority](../../compiler-design-overview.md), the [progress matrix](../../docs/progress/@entry.moth) and the [preserved behaviour](../evidence/wiring-removal-baseline.md). Record the actual activation revision in working notes. Source paths starting with `ast/`, `declaration_syntax/`, `hir/` or `public_interface/` are under `src/compiler_frontend/`. Refresh symbol names if adjacent work has landed.

## Phase 0. Freeze the surviving contracts

- Run `moth tests --tag wiring --terse` against the last live implementation. Compare outputs and target verdicts with the preserved evidence. Account for every registered `wiring_*` case, embedded Moth in Rust, host-ABI fixtures, highlighting tests and public/trait/generic projection controls. Search both dedicated names and non-prefixed callers of the affected symbols.
- Assign each case one disposition: remove an obsolete language rule, move a genuine ordinary-language check to its normal owner, or carry a callback-specific witness into the evidence record. Where replacing a test, identify the concrete wrong outcome that its surviving assertion must catch. The evidence file outlives this plan. Keep historical audits and measurements attributed to the compiler that produced them.
- **Phase 0 audit.** Run the [full phase gate](#phase-gate) over the inventory and ownership map. Check the read/forward output on both targets, side effects and failure timing, public-only type dependencies and ordinary missing-field rejection.

## Phase 1. Remove the surface and its implementation in one working change

1. **Declarations and names.** Start in `declaration_syntax/type_syntax/parse.rs`, `declaration_syntax/signature_members.rs`, `headers/binding_environment/visible_names.rs` and `ast/module_ast/scope_context/lookup.rs`. Remove the special heads and reserved-name checks for Wire and Route, including import aliases and trait requirements. Their spellings become ordinary identifiers under normal naming rules. In the absence of a user declaration the former forms receive ordinary unknown-type or syntax diagnostics. Keep head-directed generic `of`, ordinary return arrows, value/access modes, trait receivers and genuine reserved names.
2. **Calls, choices and public facts.** Remove the Wire origin filter and Route-only receiving/forwarding branches from `ast/expressions/call_arguments.rs` and `choice_constructor.rs`. Ordinary `parse_choice_construct`, argument evaluation order, payload completion and exact type checks remain in use. Do not preserve partial application or add Route default handling. Trace `ParameterContract`, `PublicParameterContract`, trait surface records and generated declaration/sidecar projections through their callers. Delete variants, one-state wrappers and fields that serve only the retired contracts. Keep canonical type dependencies, public visibility, access, return, default and failure evidence for ordinary signatures. Do not add empty callback placeholders.
3. **Execution and targets.** Remove `RouteConstruct` from typed expression storage, visitors, HIR construction, remapping, validation, reachability, borrow analysis and target lowering. Remove the constructor-route scan and its flag in `src/backends/backend_feature_validation.rs`; retain the shared reachable-feature traversal. On JS, preserve `lower_variant_construct` for ordinary choices. On Wasm remove only the obsolete capability failure. Remove Wire/Route-only host checks in `src/builder/host_requirements.rs`, leaving ordinary ABI validation in force. Search diagnostics, reason keys, renderers and the code highlighter for obsolete cases and examples.
4. **Replace the live fixtures in that same change.** Register the surviving ordinary cases, remove obsolete manifest entries and retire the tag if it has no consumers. Include positive uses of the former reserved names as user-defined types or bindings, ordinary positional/named choice construction and legal import/re-export. Check missing required arguments, generic type errors, real name collisions and an unsupported legal host signature at their intended stages. Use the current pre-migration spelling. Keep independent tests for site URL routes, module/export routes, argument routing, template slots, Channels and choice tag lowering. Refresh the implementation-status entries when the code actually changes.
- **Phase 1 audit.** Run the [full phase gate](#phase-gate) at the declaration-to-backend boundaries, including unused/imported/generic paths, privacy, distinguishing diagnostics and the negative tests' actual failure stages. Commit the integrated removal only when the remaining language works without either special contract.

## Phase gate

Run **all eight kinds after each phase**: Correctness, Diagnostics, Performance, Redundancy, Tests, Style, Comments and Documentation. Follow the [audit guide](../audit-guide.md) and [kind checklists](../audit-kinds/README.md). Map a phase to concrete owners. Each run covers one kind and one area. Independent subagents may inspect in parallel, with a coordinator serializing reservations and index updates. During the baseline phase inspect the real controls, timings, diagnostics and written evidence.

Correctness records revision coverage and findings in the bug queue. Reserve a report ID before inspection for each of the seven formal kinds. Triage findings, fix every valid in-scope finding in a separate implementation task and have another reviewer repeat its witness and rerun invalidated checks. Re-audit changed evidence. Archive clean and resolved reports, update the coverage and closeout records and record reasons for disproved or superseded findings. Advance only after all eight kinds cover the phase, zero valid in-scope findings remain and the separate [Slice review](../../../AGENTS.md) is complete.
