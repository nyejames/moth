Documentation / Numbers

Numbers

Moth uses Int for signed whole numbers and Float for finite real-number values. One compiler-selected numeric profile fixes their width and precision, and the accepted design also includes fixed-width integers and binary floats, Byte and the exact Number family. The numeric families have distinct identities and local promotion rules; other conversions use explicit casts.

Arithmetic checks overflow, division errors and non-finite results. Literal spelling and operator spacing also follow one exact grammar on every backend. See Progress for current numeric support.

Choose the explanation level: Numeric types

Numeric types

Moth uses Int for whole numbers and Float for decimal numbers.

lives Int = 3
progress Float = 0.75

An Int can be used where a Float is expected:

lives Int = 3
display_value Float = lives

A Float never silently becomes an Int. That conversion can lose information, so it needs an explicit cast.

The wider numeric family

The accepted design also includes fixed-width integers (I8, I16, I32, I64, U8, U16, U32, U64), fixed-precision binary floats (F16, F32, F64), the one-byte octet type Byte and the exact Number family (Number, Number0 and Number1 through Number256).

Int and Float stay separate types. Neither is a shorthand for a fixed-width type, even when the selected width matches, because one compiler-owned numeric profile chooses the Int width and the Float precision independently. The default profile is Int32 with Float64.

Byte is not a number. It holds one octet, compares as an unsigned byte value and needs an explicit conversion to U8 before any arithmetic. A {Byte} is an ordinary collection rather than a special buffer or text type.

Current versus accepted. The Alpha compiler implements Int and Float. The fixed widths, Byte and the Number family are accepted end-state and remain queued. See Progress for current support.

Moth has one closed family of numeric types plus a nominal octet type.

Int and Float

Int is Moth's ordinary signed integer type. Float is Moth's ordinary finite binary float type.

They are distinct semantic identities. Int is not an alias for I32 or I64, and Float is not an alias for F32 or F64, even when the selected profile gives them the same physical precision.

One compiler-owned numeric profile selects the two widths independently.

Int width    Float precision
32-bit       32-bit
32-bit       64-bit          (default)
64-bit       32-bit
64-bit       64-bit

An Int value has the range of its selected width.

Int width    Range
32-bit       -2147483648 through 2147483647
64-bit       -9223372036854775808 through 9223372036854775807

All four combinations are valid. The builder supplies the profile before command input materialises and before configuration compiles. No source, directive or command line syntax selects it.

The profile is fixed for a whole compilation. It applies to directly linked Moth modules, generated functions, Core and Builder source packages and Moth-source dependencies. It never varies by function, target partition or debug and release representation. Source dependencies compile for that profile. An incompatible precompiled Moth artefact is rebuilt or rejected, never silently adapted. Foreign components remain separate value boundaries with explicit foreign types.

A profile can change Int overflow limits, Float rounding and folded results. The same profile preserves behaviour across JavaScript and Wasm.

Fixed-width numeric types

signed integers:    I8, I16, I32, I64
unsigned integers:  U8, U16, U32, U64
binary floats:      F16, F32, F64

Each fixed integer type names its width and signedness exactly.

Type   Range
I8     -128 through 127
I16    -32768 through 32767
I32    -2147483648 through 2147483647
I64    -9223372036854775808 through 9223372036854775807
U8     0 through 255
U16    0 through 65535
U32    0 through 4294967295
U64    0 through 18446744073709551615

F16, F32 and F64 are IEEE-754 binary16, binary32 and binary64 values.

Float, F16, F32 and F64 are finite. NaN, positive infinity and negative infinity are not valid Moth values. A boundary that could introduce a non-finite result rejects it.

Fixed integers can promote with other fixed integers inside operators; fixed binary floats can promote with other fixed binary floats. Neither family implicitly mixes with Int or Float, and fixed integers do not implicitly mix with fixed binary floats. See Promotion and Operators.

Byte

Byte is a one-byte octet value. It is nominally distinct from U8, I8 and Char.

raw Byte = 255
  • Byte values support equality and unsigned-octet ordering.
  • A contextual whole-number literal from 0 through 255 initialises a Byte. A negative value cannot.
  • Byte takes no part in arithmetic, unary minus or numeric promotion, and it has no range-loop domain.
  • Explicit Byte and U8 conversion is infallible in both directions. Other numeric Byte conversions compose through U8.
  • {Byte} remains an ordinary collection. Compact physical storage does not create a buffer source type or a binary text encoding.

Number and NumberN

Number is an arbitrary-precision integer at scale zero. Number0 is the accepted spelling alias for that same scale-zero identity. Number1 through Number256 are arbitrary-precision scaled integers representing coefficient / 10^scale.

Scale is part of the semantic identity. Number2 and Number4 are different types, even for a value with no fractional digits. Leading-zero scales such as Number01 and scales above 256 are rejected.

large Number = 1000000000000000000000
money Number2 = 12.34
  • Whole literals materialise exactly at any scale.
  • A decimal or exponent literal must be exactly representable at the receiving scale, including exact integrality at scale zero. money Number2 = 1.239 is invalid rather than rounded.
  • Integer-to-Number conversion and scale widening are exact and infallible. Scale narrowing and Number-to-integer conversion are exact or fail.
  • Binary floats and Byte never participate in Number arithmetic implicitly.
  • Canonical Number text trims fractional trailing zeroes, never uses exponent notation or negative zero and always writes a leading zero before a fractional value.

Number is an immutable value. It is not a source-visible BigInt and it adds no numeric trait or overload system.

Promotion

Int may promote to Float at a contextual numeric boundary.

count Int = 3
ratio Float = count

Mixed Int and Float arithmetic produces Float. The conversion rounds at the selected Float precision.

There is no implicit Float -> Int conversion. Use a fallible explicit cast at an Int target.

Typed Int and Float values do not implicitly mix with fixed-width values. Fixed integers and fixed binary floats also require an explicit conversion to mix with each other. Compatible fixed integer / operands first select their common integer type, then divide as F64. Byte never participates in numeric promotion.

Widening between fixed integer operands inside an operator is operator promotion, not a general receiving conversion. It never narrows, and it never makes an already typed value convertible at an arbitrary receiving boundary. An implicit receiving boundary never narrows an already typed numeric value.

Bool and Char are not numeric types.

Implementation status

This reference owns the accepted contract for the complete numeric family. Progress owns current compiler and backend support. The Alpha compiler implements the default profile's Int and Float only. It does not execute the fixed-width, Byte or Number families yet.

MON data boundary

MON literal data reuses the source numeric spelling but keeps whole-number and decimal or exponent categories lossless until the receiving schema is known. Its conversion rules, profile handling and scale limits belong to the MON format contract. See MON format.

Numeric literals

A whole number with no typed destination is an Int value:

score = 42

A number with a decimal point is a Float value:

progress = 0.5

Large and tiny values can use lowercase e notation:

population = 1e6
tolerance = 1e-6

Keep a minus sign attached to the value:

temperature = -5
opposite = -count

1E6, +1 and - count are not valid numeric forms.

Typed destinations

A literal takes its type from the type it is received into, so explicit-width and exact values need no intermediate Int or Float:

small U8 = 200
large U64 = 18_000_000_000
half F16 = 0.5
raw Byte = 255

Whole literals can also initialise binary floats. Decimal or exponent spelling never initialises a fixed integer, Int or Byte merely because its value is whole, and a literal that does not fit its destination is rejected. Small values never infer a narrow type by size.

Current versus accepted. The Alpha compiler still types literals as Int or Float. The fixed-width, Byte and Number destinations are accepted end-state and remain queued. See Progress for current support.

The source spelling of a number determines its natural type.

whole = 42
decimal = 0.5
large = 1e6
small = 1e-6
precise = 1.0e+21

Contract

  • A whole-number literal is naturally Int.
  • A decimal-point or exponent literal is naturally Float.
  • Value size never infers a narrow type. 1 is Int, never U8 or I8.
  • Exponents use lowercase e.
  • Uppercase E is rejected.
  • Unary + is rejected.
  • A leading - must be attached to the literal or expression it negates.
  • -1, -1e6 and -count are valid prefix forms.
  • - count is invalid.
  • No radix literals and no numeric suffixes are added to the grammar.
valid_literal = -42
valid_expression = -count

invalid_exponent = 1E6
invalid_plus = +1
invalid_spacing = - count

The invalid lines above demonstrate rejected syntax. They are not valid program forms.

Destination-aware materialisation

A literal materialises directly in the numeric type of its immediate receiving boundary. The boundary never builds another type first.

small U8 = 200
large U64 = 18_000_000_000
half F16 = 0.5
money Number2 = 12.34
raw Byte = 255
  • A whole literal may initialise a binary float or the Number family.
  • Decimal or exponent spelling does not initialise a fixed integer, Int or Byte merely because its value is integral.
  • A negative value cannot initialise U* or Byte.
  • A signed minimum materialises from its signed spelling without first rejecting the positive magnitude.
  • An integer literal must fit its receiving type's range.
  • A decimal or exponent literal must be exactly representable at a receiving Number scale. money Number2 = 1.239 is invalid rather than rounded.

An immediate concrete numeric peer may type an otherwise untyped literal before operator promotion. When channel is a U8 value, channel + 1 types the literal 1 as U8 and produces U32. The literal 300 cannot materialise as that U8 peer, so that expression needs an explicitly widened operand.

A receiving annotation does not retrospectively retag an operator's result. Already typed variables and constants keep their identities. Parentheses do not add a receiving boundary. Generic inference uses these same local rules and gains no distant conversion search.

Binary floats

A binary float literal rounds directly to its destination using round-to-nearest, ties-to-even. Inexact values such as 0.1 are valid.

  • A materialisation whose rounded result is non-finite is rejected.
  • Subnormals and signed zero are preserved.
  • Rounding happens once, at the destination precision.

MON data boundary

MON literal data reuses the same lexical spelling but keeps whole-number and decimal or exponent categories lossless until the receiving schema is known. Its strict category conversion is documented with the MON format contract. See MON format.

Choose the explanation level: Operators

Operators

Put spaces around symbolic operators.

total = left + right
count += 1

Moth uses words for equality and logic:

same = left is right
different = left is not right
ready = loaded and valid
retry = timed_out or disconnected
blocked = not ready

Division has two forms:

real_result = 5 / 2
whole_result = 5 // 2

/ produces a real Float result. // performs integer division and produces an Int.

Use templates to join text:

greeting = ["Hello, ", "Priya"]

Templates handle all string joining and interpolation. + is for numbers only.

Typed widths

Int and Float are the ordinary arithmetic types. Fixed-width values do not mix with them or with each other silently. A fixed-width operator first promotes both operands to a common type chosen from their complete ranges, and some pairs, such as I64 and U64, have no common type and are rejected. Fixed integer / produces F64, while // stays integer division.

Unary minus is invalid on every U* value, including a known zero. Convert to a signed type first. Byte takes part in no arithmetic at all.

A compound assignment such as += computes in the promoted type and then checks that the result fits the left-hand type.

Fixed-width arithmetic is accepted end-state and remains queued. See Progress for current support.

Moth keeps equality and logical operators readable.

same = left is right
different = left is not right
ready = has_input and is_valid
should_retry = timed_out or disconnected
blocked = not ready
  • and and or require Bool operands.
  • not requires one Bool operand.
  • Symbolic equality and symbolic logical-not forms are not language operators.

Arithmetic results

The convenience family for Int and Float is unchanged.

  • Int, Int with +, -, *, %, ^, // produces Int
  • Int, Int with / produces Float
  • Float, Float with +, -, *, /, %, ^ produces Float
  • mixed Int and Float with +, -, *, /, %, ^ produces Float

The implicit Int to Float conversion remains and rounds at the selected Float precision. There is no implicit Float to Int conversion.

Typed Int and Float values do not implicitly mix with fixed-width values. Fixed integers do not implicitly mix with fixed binary floats; within each family, the operator rules below select a common result domain. The same cross-family restriction applies to comparisons, except the existing Int and Float comparison relationship. Byte has no arithmetic operators.

Fixed integer arithmetic

For +, -, *, //, % and ^, fixed integer operands first select one common type from their complete ranges. The selection ignores known values and the receiving context.

  • Same signedness selects the wider operand width, with a minimum of 32 bits.
  • Mixed signedness selects the smallest signed type, at least 32 bits, that represents every value of both input types.
  • No available common type is a source diagnostic.
U8 + U8 -> U32             I8 + I16 -> I32
U8 + U16 -> U32            I16 + U16 -> I32
U32 + U64 -> U64           I32 + U32 -> I64
I32 + I64 -> I64           I64 + U32 -> I64
I64 + U64 -> invalid       I32 + U64 -> invalid

There is no unsigned reinterpretation and no implicit arbitrary-precision fallback.

Compatible fixed integer / operands use the same common-integer eligibility rule, then convert to F64 and divide. / produces F64 in every profile.

// is integer division on the common integer type. It truncates toward zero. % follows the dividend's sign. ^ is exponentiation, not XOR.

  • A signed minimum divided by -1 overflows its result type.
  • Its remainder by -1 is zero and does not inherit the division overflow check.
  • Zero divisors and invalid integer exponents are checked. See Checked arithmetic.

Unary minus

Unary minus on a typed U* value is a compilation error, including U8 and a known zero. Cast to a signed type first. There is no automatic signed promotion for unary minus.

Signed narrow integers use the corresponding I32 arithmetic domain. I32, I64 and Int negation checks its own result limits.

Fixed binary float arithmetic

Fixed binary float arithmetic uses the wider operand precision with a minimum of F32.

  • F16 with F16 produces F32
  • F16 with F32 produces F32
  • F32 with F32 produces F32
  • any F64 operand produces F64

// is unavailable on binary floats. Unary negation uses the same minimum F32 precision.

Float keeps its profile-selected type. It does not implicitly mix with F16, F32 or F64.

Every semantic operation rounds its result. All binary float values are finite, so an operation that would produce a non-finite result fails. Comparisons use numeric values and treat positive and negative zero as equal.

Number arithmetic

  • Same-scale + and - are exact.
  • Multiplication computes the exact product and rounds to the result scale using half-even.
  • Positive-scale / checks for a zero divisor and rounds to the result scale. Scale-zero / is invalid.
  • Scale-zero // truncates toward zero and % is the integer remainder.
  • Positive-scale // is invalid. Positive-scale % is a decimal remainder at that scale.
  • Unary minus is exact.
  • NumberN ^ Int takes a non-negative exponent and rounds half-even where needed. The exponent is an Int, never a silently converted Number.

Rounding happens at every language operation result, not only at assignment or final formatting.

Ordinary mixed Number arithmetic and comparison can scale Int and every fixed integer exactly into the Number operand's scale. Different Number scales require an explicit conversion. Binary floats and Byte never participate implicitly. Fixed integer arithmetic never falls back to Number on overflow.

Comparisons

  • Any two fixed integer types compare exactly, including I64 and U64. No arithmetic common type is needed and no value converts through a binary float or a subtraction. Negative versus unsigned ordering keeps its true order and every 64-bit value compares exactly.
  • Fixed binary floats compare by numeric value.
  • Int and Float support equality and ordering, including mixed numeric comparisons.
  • Byte supports equality and unsigned-octet ordering with another Byte only.
  • Number compares with another Number at the same scale, with Int and with fixed integers through the exact mixed rule above.
  • Char supports equality and ordering.
  • Bool supports equality only.
  • String supports is and is not. It does not support ordering operators.
  • Choices and options have additional equality rules in their own references.

+ is a numeric operator only. Source string concatenation uses templates. See Strings and characters for the canonical concatenation form.

Compound assignment

+=, -=, *=, /=, //=, %= and ^= compute in the normal promoted domain of the operator, then perform a checked conversion to the left-hand type. This is the deliberate receiving-context exception that allows a typed value to narrow.

  • The place and the right operand are evaluated once.
  • The store happens only after the arithmetic and the conversion both succeed.
  • /= on an integer operand uses the / result, so it converts the Float result back to the left-hand type through the specified float-to-integer conversion. Use //= for integer division.

Precedence and associativity

From highest to lowest:

  • level 6: unary not, unary -
  • level 5: ^
  • level 4: *, /, //, %
  • level 3: +, -
  • level 2: is, is not, <, <=, >, >=
  • level 1: and
  • level 0: or

^ is right-associative. Other binary operators are left-associative.

Parentheses override normal precedence.

Spacing

Symbolic binary operators require spaces on both sides. Assignment = follows the same outer-spacing rule, but it is not a binary operator.

total = left + right
count = 1

These forms are invalid:

-- INVALID: missing required spacing
total=left+right
count=1

The compound forms +=, -=, *=, /=, //=, %= and ^= follow the same rule:

count += 1
count //= 2

count+=1, count +=1 and count+= 1 are invalid.

The mutable declaration spelling ~= stays adjacent. It needs whitespace before ~ and after =:

count ~= 1

count~= 1, count ~=1 and count ~ = 1 are invalid.

Operator overloading is outside Moth's language design. Operators remain compiler-owned and predictable.

Checked arithmetic

Moth checks arithmetic instead of quietly wrapping or producing invalid floating-point values.

These operations can fail:

  • overflowing an integer type
  • dividing by zero
  • using an invalid integer exponent
  • producing NaN or infinity

A function with an Error! return can pass that failure through its normal error path:

divide |left Int, right Int| -> Float, Error!:
    return left / right
;

Outside that kind of function, an unexpected runtime numeric failure stops the current program path.

A failure the compiler can prove in advance is reported during compilation.

Each operation checks its own result type rather than the storage width of its operands. Fixed-width arithmetic follows the same rules and remains queued with the fixed-width types. See Progress for current support.

Runtime numeric operations are checked.

Checked results

Every operation checks its semantic result type, not the operands' storage widths. A U8 and U8 sum is a U32 value and needs no 8-bit mask. U32 operations still need overflow checks even where a backend uses a wider carrier. A narrow store is permitted only after a source-level range proof or a check.

Failures

Failures include:

  • integer overflow
  • division or remainder by zero
  • invalid integer exponents
  • non-finite binary float results
  • a Number operation with a zero divisor
  • a compound assignment whose promoted result cannot convert back to the left-hand type

Failure mode

When the enclosing function has builtin Error! as its error return slot, checked numeric failures use that error channel.

divide |left Int, right Int| -> Float, Error!:
    return left / right
;

ratio = divide(10, 0) catch:
    then 0.0
;

Custom fallible channels, non-fallible functions and entry-selected top-level runtime code use trap mode for checked numeric failure. Custom error channels gain no implicit adapter.

Numeric operators remain ordinary source expressions. The compiler lowers their failure path. They are not source-visible Error! values that can be handled in the middle of an arbitrary expression.

Conversion failure is separate

A cast failure is a conversion failure, not an operand's numeric failure. cast, cast! and cast ... catch handle conversion failure only and never catch an operand's numeric failure. See Fallible casts.

Compile-time failures

A statically known numeric failure is a compile-time diagnostic.

This remains true inside a function with builtin Error!.

Statically rejected numeric forms are also diagnostics. They include unary minus on a typed U* value, a fixed integer operation with no common type, // on a binary float or a positive-scale Number, and a literal that cannot materialise at its receiving type. See Operators and @./#numeric-literals (Numeric literals).

Optimisation

A compiler proof, such as a proven range or a proven narrowing, can remove a runtime check or fold an operation. It never changes source validity, failure order or Number rounding, and effectful operands still evaluate.

Constant folding follows these same operator results and failure rules, so a folded program observes the same value or the same diagnostic as the runtime path.

Related behaviour

Range-loop counter updates use the same checked numeric operations.

Conversions that may lose information, such as Float -> Int, belong to the Casts documentation rather than implicit arithmetic coercion.
