PROGRESS MATRIX

This page tracks current implementation and target status for Moth's accepted core language, compiler, build-system and backend design. Package APIs and project-builder-specific behaviour are tracked separately in Packages and Builders Progress.

Accepted deferred surfaces may appear here. Open design questions and outside-scope mechanisms do not. Permanent language exclusions live in Design scope.

Invalid-form diagnostic coverage may appear inside the row for the intended feature. This page is not a full language reference, roadmap, exclusion inventory or test manifest.

The compiler and memory design references may describe accepted end-state architecture that has not fully landed. This matrix determines general compiler support today. For live borrow checker implementation and Boracle work, use the production borrow checker tracker rather than maintaining a second status inventory here.

Exact numeric types are delivered. The integration suite, harness, benchmarks, first-party sources and executable documentation use exact numeric types, and the harness rejects the retired numeric_profile key. The delivered cast and external-boundary contracts use one plain cast spelling, exact source/target evidence, occurrence-local authored safety catches and precision-aware foreign float validation. The frontend and HTML-JS use exact-width numeric identities, I32/F64 defaults, type-preserving equal-width arithmetic and body-local numeric constraints through known shapes, generic signatures and direct generic constructors. Receiver conflicts report their witnesses in authored order. Handler fallback constraints participate before defaulting, while every authored group receives validation without dead groups contributing to inference. Core Math, Random and Text registrations use exact F64/I32 types, and numeric proofs carry no profile stamp. Build inputs accept every fixed integer and binary-float contract and keep command numbers as literals until the exact contract materialises them; MON exposes only exact-width values; no numeric profile selection remains. HTML-Wasm rejects every user aggregate holding a fixed-width scalar before lowering, and it cannot interpolate a runtime Bool into a template.

JS/HTML delivers most of the accepted implicit-failure and entry Error! contract: private propagation, expression-wide catches, eligible authored safety catches, success-only runtime fragment publication and moth dev entry-error reporting. Wasm rejects recoverable numeric failure explicitly; a safety catch whose handler is pruned after convergence publishes no backend requirement and does not gate Wasm. Conservative proof discharges Add, Subtract, Multiply and Negate over fixed-width integer domains with full-range containment; other domains are excluded from that discharge; the checked-arithmetic reference states which operations can fail.

The compact typed-expression foundation, type and folding reductions, bounded Wiring foundation, trusted Core constant evaluation and owner hardening are implemented. Fresh Windows Canvas/frontend proof remains pending.

Use this together with tests/cases/manifest.toml when changing language features.

How to read and edit this page

  • Keep rows focused on current compiler, core build-system and backend behavior.
  • Put package and project-builder status in Packages and Builders Progress.
  • Put user-facing explanations and examples in docs pages under docs/src/docs/**.
  • Put implementation sequencing, active project plans and proposals that have not been accepted as design in docs/roadmap/roadmap.md.
  • Put accepted end-state architecture in the relevant compiler, memory or language design reference even when the implementation is incomplete.
  • Put compiler architecture and stage ownership in docs/compiler-design-overview.md.
  • Put contributor workflow, benchmarking and tooling details in CONTRIBUTING.md.
  • Prefer short coverage summaries over long fixture lists unless fixture names identify a fragile surface.
  • Use the status labels from this page's legend. Put nuance such as removed, reserved, not Alpha or backend-specific in the notes column instead of inventing new status labels.

Alpha target

The supported Alpha target is:

  • frontend parsing and diagnostics
  • typed AST construction
  • HIR lowering
  • borrow validation
  • JavaScript backend
  • HTML project builder
  • docs-style static site generation
