Moth language cheatsheet

Moth is a small, statically typed language with first-class string templates, explicit mutable access and mandatory borrow and lifetime validation.

This cheatsheet describes the accepted final language design, which can exceed current compiler support. The progress matrix and roadmap are the authorities for implementation and sequencing. Check the linked language references before assuming an ambiguous form is valid.

Syntax and names

: opens a block and ; closes it. Semicolons do not end statements. Indentation aids reading but does not define scope. Statements run in source order.

if ready:
    io.line("ready")
else
    io.line("waiting")
;
  • -- starts a line comment in code. In template bodies it is text. Use $note or $todo for discarded template content.
  • Names never shadow visible values, types, aliases, dependencies or builtins, including in parameters and child scopes. Separate scopes may reuse names when neither sees the other.
  • Variables and functions use snake_case, types and generic parameters use PascalCase and traits use ALL_CAPS.
  • Identifiers start with a letter or _ and continue with letters, digits or _. Unicode letters are allowed. Leading underscores and changes of case cannot escape reserved names, including none/None.
  • Ordinary names such as config, Config, project, block, group and region are not keywords. $config and @project have their own meanings.
  • There is no general bare lexical block or control-flow label. A name: statement opens a declared region. Exact _: is invalid.

Symbolic binary operators and assignment require spaces on both sides. Keep compound tokens together:

count ~= 0
count = left + right
count += 1
count //= 2
-- Invalid: count=1, left+right, count+=1, count ~ = 0

Values, bindings and constants

name = "Priya"              -- inferred, immutable
age Int = 30                -- typed, immutable
ready Bool = true
letter Char = 'm'

count ~= 0                  -- inferred, mutable
names ~{String} = {}         -- typed, mutable
count = 1                   -- reassignment

site_name #= "Moth"          -- inferred compile-time constant
version #Int = 1            -- typed compile-time constant

= declares a new binding or reassigns an existing mutable binding. ~ controls access, not type identity: names above has type {String}. # controls compile-time evaluation, not visibility, and cannot combine with ~.

Ordinary bindings and constants need initialisers. Constants are immutable and fully evaluate from compile-time values. Use earlier same-file constants or dependency-bound constants, not same-file forward references. Cross-file constants follow dependency order. Cycles are invalid.

Only Core functions with a documented constant-evaluation contract can fold calls. # does not make ordinary function or host calls executable at compile time. $config input declarations have separate fallback and omission rules under Project configuration.

Strings and characters

Quoted text and templates share one String type. Char supports equality and ordering. Bool supports equality only.

escaped = "Hello\nworld"
greeting = [: Hello, [name].]
joined = ["Hello, ", name]
same = "Moth" is [: Moth]

Quoted strings accept only \\, \", \n, \r and \t. A backslash cannot continue one across a physical newline. Backticks do not create source strings.

Use templates for concatenation and interpolation. String + String is invalid. is and is not compare content regardless of string origin. Strings have no ordering, indexing or in-place character mutation. A mutable string binding can be reassigned.

Const records

settings #= (
    title = "Moth",
    window = (width = 800, height = 600),
)
width #= settings.window.width
empty_record #= ()

Every record field has a unique name and an explicit value. Initialisers use the surrounding scope, not earlier field labels. Nested anonymous records and explicit named constructors are allowed. All fields must fold.

A whole const record is a compile-time field group. Read its ordinary fields in runtime code. Do not pass, return or store the record itself at runtime or call runtime methods on it. This also applies to fully folded struct constants used as const records. Runtime anonymous records have a separate contract below.

MON (Moth Object Notation) is the compiler's official serialisation format, deliberately sharing Moth's core value and construction syntax. See MON for its data contract.

References, copies and lifetimes

Existing values use shared read-only access when bound, passed, returned or stored. Live shared aliases block overlapping mutation:

items ~= {1, 2}
view = items
size = view.length()
~items.push(3)             -- valid: view has no later use

independent ~= copy items
outer = {items}            -- new outer collection, shared inner items

A later use of view would invalidate the mutation. Last use follows control flow, not lexical scope alone. A fresh outer aggregate does not copy existing children.

A mutable declaration from an existing mutable place creates an exclusive write-through alias:

same_items |value {Int}| -> {Int}:
    return value
;

original ~= {1}
writer ~= original
writer = {2}              -- original now holds {2}

returned ~= same_items(original)
returned = {3}            -- original still holds {2}

Returned values get separate caller bindings even when they alias existing allocations. Reassignment changes only that binding. Fallible success values and multiple results may alias parameters or one another.

copy deep-copies a binding, field projection or parenthesised place. It preserves internal sharing without sharing mutable storage with the source. Any non-copyable member rejects the whole copy. Opaque handles and resources are non-copyable unless their contract defines an independent copy. Literals, templates, calls and computations are not places.

~place requests exclusive access for one operation. It neither copies nor moves. Referenced storage must live at least as long as its container. Field and element aliases retain their containing storage. A value may outlive its original binding, but independently ending lifetimes need a common owner or copy.

Moth has no explicit reference types, lifetime annotations or move operator. Access and lifetime rules apply under every backend and build profile.

Declared regions

Only an explicit into name declaration places storage in a declared region. Lexical containment alone does not. Write placement after access/type syntax and before =:

request:
    scratch:
        temporary String into scratch = [: temporary]
        saved String into request = copy temporary
    ;

    io.line(saved)
;
  • Place a fresh result with legal retained references or an independent copy. into cannot adopt an existing alias.
  • Target the current or an enclosing declared region. Ancestor placement requires straight-line nested regions, with no intervening conditional or repeated construct, even if true:. The name stays visible in the destination scope after the inner region ends.
  • For conditional production, declare in the destination scope with an if, match or catch initialiser. Loops can mutate an aggregate already placed there.
  • Children may retain parent-owned values. Parents and siblings cannot retain child-owned values. No region-owned value or alias may escape its region.
  • A reference cycle, including a copied cycle, belongs wholly to one declared region.
  • Region-owned storage stays until exit and is reclaimed together on every path, including returns, loop exits and recoverable failure.
  • Reassignment preserves region ownership. Use fresh storage, an independent copy or a same-region value at proven final use. It cannot create a borrowed alias of outside storage.

Regions are not values or types. into is declaration-only, with no extraction, adoption or unrestricted transfer.

Further detail: Memory.

Numbers and operators

  • Int, Uint and Float: signed integer, unsigned integer and finite binary float.
  • I8, I16, I32, I64, U8, U16, U32, U64: fixed-width integers.
  • F16, F32, F64: fixed-precision binary floats.
  • Dec/Dec0, Dec1 through Dec256: arbitrary-precision exact values.
  • Byte: a one-byte octet outside arithmetic.

One numeric profile selects Int width and Float precision independently, each 32 or 64 bits, for the whole build. Uint follows the selected Int width, so it is Uint32 under Int32 and Uint64 under Int64. The default uses 32-bit Int and 64-bit Float, and therefore Uint32. Their identities remain distinct from the fixed-width types. Binary floats allow subnormals and signed zero, never NaN or infinities.

Literals

small U8 = 200
total U32 = small + 1
count Uint = 1 + 2
half F16 = 0.5
price Dec2 = 12.50

Whole literals naturally infer Int, decimal/exponent literals Float. Size never selects a narrower type. A receiving type materialises a literal directly. An immediate typed numeric peer can supply that type before promotion: small + 1 types 1 as U8, then produces U32. small + 300 is invalid. An annotation cannot retag an operation or an already typed value. A Dec receiver goes further and types unresolved literal arithmetic: total Dec4 = 1 + 1 holds 2 and total Dec4 = 0.1 + 0.2 holds exactly 0.3. A typed Dec peer supplies its scale to a literal-only opposite operand from either side. A Uint receiver and peer do the same for whole-number arithmetic: count Uint = 1 + 2 holds 3, while a typed Int never becomes Uint through a peer. Their exponent rules differ: a Dec exponent stays Int, a Uint exponent stays Uint.

  • Whole literals can initialise floats, Uint and Dec. Decimal/exponent spelling cannot initialise Int, Uint, fixed integers or Byte merely because its value is whole. Negative values cannot initialise U*, Uint or Byte. Signed minima materialise directly from their negative spelling. Binary float literals round once at destination precision, nearest with ties to even. 0.1 is valid.

Use lowercase e, as in 1.0e+21, and underscores between digits. Uppercase E, radix literals, suffixes, unary + and spaced - count are invalid.

Arithmetic and comparison

  • Int/Int produces Int for + - * // % ^, Float for /. Mixed Int/Float arithmetic produces Float. Receiving Int -> Float promotion may round. Reverse conversion needs a cast.
  • Uint/Uint produces Uint for + - * // % ^, checked against the selected unsigned range, and Float for /. Mixed Uint/Float arithmetic produces Float. Receiving Uint -> Float promotion is direct and infallible. Reverse conversion needs a cast.
  • Uint/Int arithmetic in either order needs an explicit conversion, including / and ^. Uint underflow is failure, not an Int result. Uint also needs an explicit conversion to mix with fixed-width values.
  • Fixed integers promote together, as do fixed floats. Neither family implicitly mixes with typed Int/Uint/Float, and fixed integers do not implicitly mix with fixed floats.
  • Fixed integer + - * // % ^ select a common type from complete operand ranges. Same signedness takes the wider width, at least 32 bits. Mixed signedness takes the smallest signed type, at least 32 bits, holding both ranges. I32 + U32 -> I64. I64 + U64 and I32 + U64 have no common type and are invalid.
  • Fixed integer / requires that same common integer type, then converts to and produces F64.
  • Fixed float arithmetic uses the wider precision, at least F32, rounding each result. Binary floats have no //.
  • Unary minus rejects typed U* and Uint, including zero. I8/I16 negation produces I32, F16 negation F32. Wider signed types and Int check their own limits.
  • // truncates towards zero and % follows the dividend's sign. The result type's signed minimum // -1 overflows, but its % -1 is zero. ^ means exponentiation.
  • Any fixed integer types compare exactly, including I64/U64, without an arithmetic common type. Int/Float support mixed comparisons. Uint/Uint and Uint/Int compare exactly, while Uint/Float converts directly then uses float comparison. Other family restrictions still apply. Positive and negative floating zero compare equal.

Checks use the operation's result type. U8 + U8 yielding 256 is valid U32. Overflow, zero division and invalid exponents follow the enclosing error contract or handler, without wrapping or implicit panic. Statically known failures remain diagnostics inside catch.

Compound += -= *= /= //= %= ^= evaluate the place and right operand once, compute in the promoted domain, then check conversion back. They write only after both checks succeed. Right-hand catch does not cover the later operation or conversion. Integer /= converts the floating result back. A Uint /= has a Float result before checked conversion back. Use //= for integer division.

Precedence, highest first: unary not/-, ^, * / // %, + -, comparisons, and, or. ^ associates right, other binary operators left. Parentheses override precedence.

Logical operators require Bool and short-circuit: and skips its right operand when the left is false, or when the left is true. Equality uses is/is not. + only adds numbers.

Byte

Byte accepts whole literals 0 through 255 and compares only with Byte, using equality or unsigned-octet ordering. Byte has no arithmetic, unary minus, promotion or range domain. {Byte} adds no buffer or encoding API.

Dec and DecN

Dec is a scale-zero arbitrary-precision integer, also spelt Dec0. Dec1 through Dec256 store coefficient / 10^scale. Scale determines type identity. Dec01 and scales above 256 are invalid.

Literals must fit the scale exactly. price Dec2 = 1.239 is invalid. Decimal/exponent spelling can initialise scale zero when exactly integral.

  • Same-scale +/- and unary minus are exact. Multiplication rounds its exact product half to even. Positive-scale / and exponentiation also round half to even at each result.
  • Scale zero permits ///%, not /. Positive scales permit //%, not //.
  • DecN ^ Int requires a non-negative exponent, never silently converted to Dec. Context reaches the base but never the exponent. A typed Uint exponent needs an explicit handled cast to Int.
  • Int, Uint and fixed integers scale exactly into the Dec operand's scale for arithmetic/comparison. Different scales need explicit conversion. Floats and Byte never mix implicitly.
  • A Dec or Uint receiver types unresolved literal arithmetic at its scale or unsigned width before operator selection. Their exponent rules differ: a Dec exponent stays Int, a Uint exponent stays Uint. See Numeric literals for the receiving and peer contract.

Decimal text trims fractional trailing zeroes, includes a leading zero before fractions and uses neither exponent notation nor negative zero.

Explicit casts

cast takes its target from the immediate typed receiving boundary:

octet U8 = 42
count U64 = cast octet
label String = cast count

narrow_sum |left U32, right U32| -> U8:
    value U8 = cast left + right catch then 0
    return value
;

narrow_sum catches both U32 addition overflow and failure to convert its result to U8.

  • Plain cast needs infallible evidence unless an enclosing catch handles the conversion. Even an infallible conversion can have a failing operand.
  • cast! needs fallible evidence and a built-in Error! return slot, including at top level. It cannot share an expression with catch.
  • Typed declarations, assignments, returns, concrete parameters, fields, defaults, container entries, assertion arguments and explicitly received then arms supply targets.
  • Untyped declarations, conditions, operators, template interpolation, expression statements and parentheses do not. Generic inference does not look through cast.
  • Same-type casts and conversion constructors such as Int(value) are invalid. Error(...) is a real constructor. Cast targets are builtin types, not user-defined types.

Conversion rules

Fallibility follows the complete source and target types, not a known safe value.

  • Integer-to-integer conversion preserves the value. It is infallible only when the complete source range fits the target. Uint and Int need an explicit cast between each other in both directions, even when the values would fit.
  • Integer-to-F32/F64 conversion is infallible and may round. Uint64 converts directly without a binary64 intermediate. Integer-to-F16 conversion is infallible only when the complete source range fits its finite range.
  • Uint -> Float is infallible and direct at the selected precision, and also available implicitly at value-receiving and mixed-operator boundaries.
  • Binary-float precision widening is infallible. Narrowing is fallible and rounds directly to the destination, once, to nearest with ties to even. Precision loss alone succeeds. A rounded non-finite result fails.
  • Float-to-integer conversion is fallible: truncate towards zero, then check the destination range. Float -> Uint rejects negative results below zero, while -0.5 truncates to zero and succeeds.
  • Uint -> Dec/DecN is exact and infallible. Dec/DecN -> Uint is exact-or-fail with integrality and unsigned range checks.
  • Byte <-> U8 is infallible. Other numeric and text conversions involving Byte go through U8. Uint has no direct conversion with Byte, Char or Bool.
  • Integer-to-Dec/DecN and decimal scale widening are exact and infallible. Scale narrowing and decimal-to-integer conversion are exact-or-fail, never rounded.
  • Numeric text casts are fallible and consume the whole string. They reject surrounding whitespace, unary +, uppercase E, malformed separators or exponents, NaN and infinities. Unsigned Uint text additionally rejects a leading -, including -0. Numeric formatting to String is infallible, with Byte going through U8. Uint zero formats as 0.
  • String -> Bool trims surrounding whitespace and accepts only lowercase true or false. String -> Char requires exactly one Unicode scalar. Both are fallible.
  • Char -> Int produces its code point. Int -> Char is fallible and requires a Unicode scalar. Bool and Char convert infallibly to String.
  • String -> Error creates a message with code 0. Error -> String returns its message. Both are infallible.

Other source-target pairs are not implied. In particular, do not infer Float/DecN conversion helpers.

Optional targets

A T? target casts to inner T, then wraps the result. Its handler also supplies T, so then none is invalid. Optional operands never unwrap automatically.

parse_optional |text String| -> Int?:
    value Int = cast text catch:
        return none
    ;
    return value
;

User-defined conversions require explicit cast conformance, shown under Traits and conformance. See Casts for conversion contracts.

Functions and calls

describe |prefix String = "item", subject String| -> String:
    return [: [prefix]: [subject]]
;

label = describe(subject = "apple")
other_label = describe("fruit", subject = "pear")

Use |...| for parameters, || for none and parentheses for supplied values. Positional arguments precede named arguments. Each parameter receives at most one value. Named arguments can skip defaults. Host functions and builtin members are positional-only.

Defaults fold at compile time and cannot reference other parameters. Omit -> only when there are no return slots. An error-only function still writes -> Error!. No-success functions can fall through or use bare return. There is no Void annotation.

Mutable parameters take ~place for existing mutable storage or a plain fresh value:

increment |value ~Int|:
    value += 1
;

count ~= 1
increment(~count)
increment(1)

Shared parameters and fresh rvalues reject ~. Mutable receivers always require an existing mutable place.

Multiple returns remain separate values:

pair || -> String, Int:
    return "Priya", 2
;

name, count = pair()

Receive all results through matching multi-bind, return or value-producing syntax. All results are computed before assigning any existing targets. A comma can continue a multi-bind onto another line, but no trailing comma precedes =. There are no tuple returns. Every reachable success path returns matching values or terminates.

Never-returning calls: -> !

-> ! declares that a callable never returns control normally:

fatal |message String| -> !:
    assert(false, message)
;

require_name |ready Bool| -> String:
    name = if ready:
        then "Priya"
    else
        fatal("name unavailable")
    ;
    return name
;

-> ! replaces the whole return contract and cannot combine with other slots. Every reachable path must diverge. Fallthrough, returns and error/option propagation do not qualify.

Calls are standalone terminating statements, including in block branches. They produce no value and accept no postfix !, ? or catch. There is no Never value type or implicit conversion into another return type.

Only the explicit signature communicates divergence across calls. A wholly divergent function with no written return contract needs -> ! or its intended ordinary contract. An ordinary typed function can use assert(false) as a placeholder. Methods, generics, traits and foreign declarations preserve the exact contract.

Options: T?, none and postfix ?

T? accepts a T value or none, without an Option constructor. none needs an immediate optional receiving context. Optional values never unwrap implicitly.

find_name |id String| -> String?:
    if id is "":
        return none
    ;
    return "Priya"
;

load_label |id String| -> String?:
    name = find_name(id)?
    return [: User: [name]]
;

Postfix ? unwraps a present value or immediately returns none. The enclosing function needs exactly one success slot, of a compatible optional type. It cannot combine with catch.

Inspect absence or capture a present value:

maybe_name String? = "Priya"
label = if maybe_name is |name| then name else "guest"

if maybe_name is none:
    io.line("missing")
;

if maybe_name is:
    "Priya" => io.line("admin")
    |name| => io.line(name)
    none => io.line("guest")
;

Options of the same type support equality when their inner type does, but have no ordering or direct else then fallback operator.

Errors, propagation and recovery

One final E! slot declares typed failure. return! returns an error, postfix ! propagates through an exactly compatible caller slot and catch recovers.

load_user |id String| -> String, Float, Error!:
    if id is "":
        return! Error("Missing id", 404)
    ;
    return "Priya", 1.0
;

load_summary |id String| -> String, Error!:
    name, score = load_user(id)!
    return [: [name]: [score]]
;

name, score = load_user("") catch |err|:
    io.warn(err.message)
    then "guest", 0.0
;

Builtin Error has message String and code U32 = 0. Codes span 0 to 4294967295. An Int variable needs a fallible cast. Code 0 still represents failure. Errors can be constants or carry runtime messages. Custom errors use ordinary nominal types.

An error-only function succeeds by reaching its end:

validate |ready Bool| -> Error!:
    if not ready:
        return! Error("not ready")
    ;
;

Calls with an E! slot need ! or applicable recovery. Error! does not create a first-class Result value. Use a choice for result-like domain data.

Uses a builtin Error! entry contract

The exported rule includes methods, generics and re-exports. Traits and conformance cannot silently widen an error contract.

product |left Int, right Int| -> Int:
    return left * right
;

export:
    checked_product |left Int, right Int| -> Int, Error!:
        return product(left, right)
    ;

    product_or_zero |left Int, right Int| -> Int:
        return product(left, right) catch then 0
    ;
;

A transparent alias of Error preserves this built-in behaviour. A custom wrapper does not. Map implicit failure into a custom error explicitly:

GeometryError ::
    InvalidDimensions,
;

area |width Int, height Int| -> Int, GeometryError!:
    result = width * height catch:
        return! GeometryError::InvalidDimensions
    ;
    return result
;

Whole-expression catch

catch binds below the ordinary operators and protects the complete selected expression, including receivers, arguments, nested calls and cast operands:

load_amount |text String| -> Int, Error!:
    return cast! text
;

amount_or_zero |text String, quantity Int, fee Int| -> Int:
    return load_amount(text) * quantity + fee catch then 0
;

This handles the call's error and both arithmetic operations. Compatible typed calls inside the expression supply success values without per-call !. Explicit !, cast! and ? conflict with a catch on the same expression.

Implicit failure and built-in Error! may share a handler. A bound name then receives Error, preserving an existing typed error's message, code and identity. Producers of one custom E! may share a handler only when no implicit failure remains, and its binding has type E. Mixing distinct typed error types, including custom E and Error, is invalid. Split or map incompatible work.

Work evaluates once in source order. The first failure skips the remaining expression. Earlier mutations and IO remain visible. A handler's own failure propagates outward, without re-entering it.

Use catch: or catch |err|: for blocks, and catch then value or catch |err| then value inline. The error binding is immutable and local. A value handler supplies matching then values, returns or diverges. A no-success handler may fall through.

To recover a complete update, catch a private helper that performs it or compute the replacement under catch, including any required cast back to the destination type, then assign.

A catch needs a checked operation, inferred-failure private call or typed-error producer. An infallible call or literal alone is insufficient. Proving an eligible operation safe does not invalidate its catch.

Catch bodies cannot appear inside conditions, templates or constants, except directly foldable cast recovery at an explicit constant/default boundary. Commas, parentheses, logical lines and statements delimit the protected expression. Grouping an operand does not shrink an outer handler's scope.

Assertions

assert checks invariants in every build:

assert(ready)
assert(condition = ready, message = "must be ready")

assert is statement-only and requires parentheses. Its condition takes Bool, its message takes String? and neither accepts ~. Omitted or none messages use "assertion failed". Other types do not stringify automatically.

Failure while computing the condition follows the enclosing failure contract without evaluating the message. The message is fully checked even for a known-true condition, but evaluates only for false. It cannot escape through failure, !, ?, return, break or continue. Handle fallible message work beforehand.

Assertion failure is unrecoverable. assert(false) is statically terminal. assert cannot be imported, aliased or handled with postfix ! or catch.

To request a deliberate panic on a checked failure:

product = left * right catch:
    assert(false, "product must fit")
;

Only authored assertions deliberately request panic. Catch cannot recover them, allocation or stack exhaustion, or unexpected host/runtime faults.

Branching and value-producing blocks

Conditions use Bool. Statement else is optional. There is no statement else if: nest an if or match one value against several patterns.

label = if ready then "ready" else "waiting"

score_label = if score is:
    < 0 => then "invalid"
    0 => then "zero"
    >= 90 => then "excellent"
    else => then "other"
;

The inline then ... else ... form stays on one logical line. A block can perform work before producing its values:

label, score = if ready:
    then "ready", 1
else
    io.warn("waiting")
    then "waiting", 0
;

then sends values to an immediate declaration, assignment, multi-bind or return. These forms are not general expressions: do not nest them in arguments, operators, constructors, collections, templates or another then. Every reachable path produces matching arity and types or terminates, and at least one produces values. A real fallthrough is invalid. A single-predicate producing if requires else.

A full match uses if value is: and line-initial pattern => arms. Arms have no colon or individual semicolon. Guards use pattern if condition =>. else => is the only catch-all. A bodyless else => deliberately ignores remaining cases in a statement match.

  • Ordinary full matches require else =>, even when listed literals appear exhaustive.
  • A choice match can omit it when every variant is covered without guards. Any guarded choice arm requires it. A variant cannot appear twice.
  • An option match can omit it with both unguarded none and unguarded |name| arms. Literal and relational arms do not replace the present-value capture.
  • Relational patterns work for numeric types, Byte and Char, not String. Patterns must match the subject's type.

A compile-time-known condition selects one ordinary if branch after both branches satisfy name, type and value-production rules. The selected branch keeps its scope. This does not conditionally remove declarations, dependencies or exports.

Loops

count ~= 0

loop count < 3:
    count += 1
;

loop names |name, index|:
    io.line([: [index]: [name]])
;

loop 0 to 10 by 2 |value|:
    io.line([: [value]])
;

Conditional loops check Bool before each iteration. Collection loops capture source and length once, then visit collection order. They accept no binding suffix, |item| or |item, index|. Bindings are immutable and body-local, with an Int index starting at zero. Empty suffixes and more than two names are invalid. Maps are not collection-loop sources.

Range rules:

  • to excludes the end, to & includes it. loop to n starts at zero.
  • Direction follows the bounds. by supplies a magnitude, regardless of sign. Integer steps default to one. Any floating range needs explicit by.
  • Start, end and explicit step evaluate once, left to right. Static zero steps are invalid. Dynamic zero fails before iteration.
  • Int, Uint, Float, fixed integer and fixed float operands use normal promotion. All-Uint bounds with an optional Uint step bind Uint. Integer-only headers mixing Uint and Int need an explicit conversion. A Float bound or step instead selects Float through the direct Uint-to-Float rule, still needing an explicit by step. The value binding takes the common type, the optional index Int. Byte/Dec have no range domain.
  • Checked updates stop at the last valid value, including inclusive maxima and unsigned descent to zero. Floating candidates round before endpoint checks. Non-finite/out-of-range candidates end the loop. An in-range candidate rounded back to the current value fails.

break exits the nearest ordinary loop. continue advances its check, item or step. Neither takes values or labels. return/return! exit the function.

Repeated option capture

loop ~scanner.next_token() is |token|:
    inspect(token)
;

The header accepts any T? expression, evaluated once per attempted iteration. none exits, otherwise one immutable body-local capture receives the payload. Completion/continue re-evaluates the header. break performs no further evaluation. There is no index, special next method or implied consumption. ~ follows ordinary access rules.

Collection-producing loops

positives {Int} = loop {-2, 1, 3} |item|:
    if item > 0:
        then item
    ;
;

Any of the four loop forms can eagerly produce {T} at a runtime declaration, single assignment or one-slot return. Producing loops are not general expressions, multi-bind/multi-slot results or # initialisers.

then value appends one element and ends that iteration. Fallthrough/continue add nothing. break returns the partial collection. Each iteration contributes at most one element.

An explicit {T} supplies element context. Otherwise every reachable contribution must infer one compatible type. At least one reachable then is required. Both branches remain valid before static selection.

Branches inherit the production target. An ordinary nested loop blocks it, and a nested producing loop owns its own. Template loops support neither repeated option capture nor collection production.

Structs and receiver methods

Person = | name String, age Int = 0 |

birthday |this ~Person|:
    this.age += 1
;

display_name |this Person| -> String:
    return this.name
;

person ~= Person(name = "Priya", age = 30)
person.age += 1
~person.birthday()
person_name = person.display_name()

Fields require explicit types. Defaults must fold. Fields without defaults are required. Constructors follow normal argument routing. Matching fields imply neither type compatibility nor structural equality. Named children require their explicit constructors.

Field writes require a mutable root and valid access. Receiver methods are top-level functions with first parameter this T or this ~T. Shared calls omit ~. Mutable calls need ~place.method(...) on an existing mutable place. Free-call syntax is invalid.

Methods belong to same-file structs/choices, cannot collide with fields and follow their type's visibility. They cannot extend other types or be imported, aliased or re-exported separately.

Runtime anonymous records

show_state |title String|:
    child = (count = 3)
    state ~= (
        title = title,
        saved = child,
        fresh = (enabled = true),
    )
    state.fresh.enabled = false
    independent = copy state
    count = independent.saved.count
;

Records require non-empty, unique label = expression entries with comma separators and optional trailing comma. No positional fields, shorthand, field types or field-level mutability. Initialisers evaluate once in source order and need not fold.

Labels introduce no locals or receiving types. Earlier fields do not enter scope. Context-dependent none, empty containers and cast need earlier typed values. Runtime context selects a runtime record even for constant-looking fields. Empty () belongs only to const records.

Each literal site defines one hidden identity, preserved by repeated execution, aliases and copies. Matching fields at another site do not permit replacement assignment.

Local binding, projection, compatible assignment, copying and recursive anonymous nesting are allowed. Parents can contain existing anonymous children and explicit nominal children, without extra copying or mutation authority.

Hidden identities cannot cross any function argument/return, authored signature, nominal field, type alias, method, conformance or export, nor enter collection/map storage or generic arguments. Restrictions apply through parents, options and captures. Extracted ordinary leaves keep their own rules.

Choices

Status ::
    Ready,
    Loading | progress Float |,
    Failed | message String, code Int |,
;

ready = Status::Ready
failed Status = ::Failed(message = "offline", code = 503)

if failed is:
    Ready => io.line("ready")
    Loading(progress) => io.line([: [progress]%])
    Failed(message as reason, code) => io.error([: [code]: [reason]])
;

A choice needs at least one variant. Unit variants omit (). Payloads need non-empty, explicitly typed immutable fields, without defaults. Construction supplies every field through normal argument routing. Known expected choice types permit ::Variant(...), otherwise qualify it. Status::Failed permits no gaps around ::.

Patterns capture every exact field name in declaration order. as renames the immutable arm-local binding. Wildcards and named assignments are invalid. See Branching for guards/exhaustiveness.

Same-type equality compares tag and payload only when every possible payload type supports equality. Scalars, decimals, qualifying choices/options work. Structs, collections, maps, functions and opaque types do not. One unsupported field disables whole-choice equality, including unit variants. Choices have no ordering.

Type aliases and generics

UserId as Int
Names as {String}
MaybeName as String?
User = | id Int |

Aliases are transparent: UserId and Int interchange, while User has distinct identity. Aliases can chain, not cycle. They introduce no runtime value or constructor. Construct through the canonical nominal name.

identity type A |value A| -> A:
    return value
;

Box type A = | value A |

Maybe type A ::
    Some | value A |,
    Empty,
;

get type A |this Box of A| -> A:
    return this.value
;

empty type A || -> {A}:
    return {}
;

box Box of String = Box("Moth")
value = identity(42)
items {Int} = empty()
missing Maybe of String = Maybe::Empty
StringBox as Box of String

Generics apply to top-level structs, choices and free functions. Parameters must appear in the public signature/type shape. Receiver method parameters must align exactly with the generic constructor. Concrete-instance methods are invalid.

of supplies concrete types with matching arity. Concrete argument lists determine instance identity. Calls/constructors infer from immediate arguments or the immediate receiving result. They have no explicit call-site type arguments. Later uses, mutations, casts, outer-call parameter contexts and bare none cannot solve missing evidence. Annotate an intermediate result.

Nested inline of requires an inner alias:

Pair type A, B = | first A, second B |
StringIntPair as Pair of String, Int
paired Box of StringIntPair = Box(Pair("count", 3))

One application is allowed inside a collection element, such as {Box of String}.

Unconstrained code can pass, return, store and forward values, but cannot assume arithmetic, comparison, fields, interpolation, IO or methods. Use bounds. No where, generic function values, parameterised aliases, partial application, higher-kinded types, lifetime parameters or general const generics.

Traits and conformance

DISPLAY_TEXT must:
    display |This| -> String
;

Label = | text String |

display |this Label| -> String:
    return this.text
;

Label must DISPLAY_TEXT

render type Item is DISPLAY_TEXT |item Item| -> String:
    return item.display()
;

Requirements use This/~This receivers. Other This parameters need names. Direct return This is allowed, composed This?, {This} or Box of This invalid. Requirements have no bodies or individual semicolons. Newlines separate them, one ; closes the trait. Empty marker traits are valid.

Conformance is explicit and bodyless, without ;. Commas list traits. Same-file structs, choices and aligned generic constructors must match receiver mutability, parameter access/types and return types/channels exactly. Parameter names do not matter. Conformance remains reusable wherever type and trait are visible.

Bounds use is, as in type Item is DISPLAY_TEXT and NAMED. Commas separate parameters. Concrete arguments need visible conformance. Bound calls resolve a unique required method statically. Traits cannot serve as runtime types or values.

READABLE must not WRITABLE declares symmetric incompatibility between traits. It adds neither inheritance nor negative conformance. Type must not TRAIT is invalid.

No trait objects, dynamic dispatch, default methods, associated items, inheritance, aliases, generic traits/methods, structural or blanket/conditional/negative/specialised conformance. Use choices for runtime alternatives.

Custom cast conformance

Using Label above, provide a same-file receiver method and explicit conformance:

to_string |this Label| -> String:
    return this.text
;

Label must CASTABLE_TO_STRING

label = Label("Moth")
text String = cast label

The six source-authored families target Int, Float, Bool, String, Char and Error. CASTABLE_TO_* requires to_* |This| -> Target. TRY_CASTABLE_TO_* requires try_to_* |This| -> Target, Error!. Implement with lowercase this and the concrete type. The same-file and generic conformance rules also apply. This six-family scope is intentional: Uint carries compiler-owned builtin evidence rather than gaining source-authorable traits.

A method alone supplies no cast. Infallible and fallible conformance to one target conflict. These predeclared traits cannot be imported, exported, aliased or redeclared. Uint, fixed numeric types, Byte and DecN have no source-authored cast families.

Collections

names ~= {"Priya", "Rob"}
empty ~{Int} = {}
fixed ~{3 Int} = {10, 20}

capacity #Int = 4
scratch ~{capacity String} = {}
labels {capacity} = {"a", "b"}

{T} is growable, {N T} has maximum capacity N. All items share one element type. Element type and fixed capacity cannot change through mutation. Growable/fixed forms and different capacities are incompatible.

Empty literals need explicit type. Empty fixed bindings must be mutable. Explicitly typed fields may default empty. Capacity accepts only a positive Int literal or bare #Int name. {capacity} shorthand requires an immediate non-empty literal in a binding.

Hash maps

scores ~{String = Int} = {"Priya" = 10, "Rob" = 8}
empty_scores ~{String = Int} = {=}

{Key = Value} requires one key/value entry form throughout. Bare key names read variables. {} always denotes a collection. Empty {=} needs a known map type.

Keys: String, Int, Uint, Bool, Char, fixed integers or Byte. Typed keys cannot cross nominal/width boundaries. Contextual literals use the declared key type. Floats, Dec, user types and generic parameters are invalid keys.

Replacement preserves insertion position and stored key. Removal then reinsertion appends.

  • scores.get(key): shared value, fallible.
  • scores.contains(key): Bool, infallible.
  • ~scores.set(key, value): inserts/replaces, no value, fallible.
  • ~scores.remove(key): removed value, fallible.
  • ~scores.clear(): removes all entries, no value, infallible.
  • scores.length: read-only Int property, no parentheses.

Arguments are positional-only, lookup keys borrowed. Failed mutations preserve contents. A live get alias blocks mutation. No indexing, collection-loop iteration, entry API, fixed capacity, equality, sets or custom key/hash policy. Inline map nesting beyond two levels needs an inner type alias.

Templates

Templates produce String values, folding static work and evaluating the rest at runtime. : separates head values, helpers, directives and slot contributions from the body.

content = [$md:
    # Hello [name]
]
literal = [: ["[brackets]"]]

Insert a quoted string to emit literal square brackets.

Directives and formatting

  • $md formats Moth Markdown. $raw preserves body text and whitespace.
  • $note and $todo discard balanced bodies. $doc marks documentation comments.
  • The HTML builder supplies $html for raw HTML, $css for CSS checking/formatting and $escape_html for escaping HTML-sensitive text.
  • $code("language") highlights literal code without nested template interpretation. It removes formatting indentation while preserving relative indentation.

Formatters affect only their own template. Incompatible formatters cannot share a head.

A .mtf file folds an implicit $md body into content #String. See Moth template files.

Slots and child wrappers

card #= [:
    <h1>[$slot("title")]</h1>
    <section>[$slot]</section>
]
[card:
    [$insert("title"): Welcome]
    Hello, [name].
]

image #= [: <img src="[$slot(1)]" alt="[$slot]">]
[image, "logo.png": Moth logo]

list #= [$children([:<li>[$slot]</li>]): <ul>[$slot]</ul>]
[list: [: one] [$fresh: [: two]]]

Positive integer slots receive loose head contributions in ascending order, then the default slot receives any remainder. Unassignable content causes an error. Missing slots render empty and repeated slots replay content.

$children(...) wraps direct child templates. $fresh skips one immediate parent wrapper, preserving wrappers inside that child.

Template control flow

Place if or loop last in the head, after a comma when another head item precedes it:

[card, if maybe_name is |name|:
    Hello [name]
[else if use_fallback]
    Hello fallback
[else]
    Hello guest
]

[loop items |item, index|:
    [index]: [item]
]

Template if accepts Bool conditions or option captures, evaluates only the selected branch and supports else if, but no full match-arm chains. Conditional, collection and range loops concatenate output without separators. Structural [break] and [continue] target the nearest template loop.

A loop-head wrapper wraps the aggregate once. Put per-iteration wrappers in the body. Structural no-output skips wrappers, while a selected empty branch may render its wrapper. Selected runtime content can propagate ! through its enclosing function, but cannot use catch blocks as expressions.

Const templates validate every branch and fold the selected work. Const range/collection loops obey template_const_loop_iteration_limit (default 10_000, maximum 1_000_000). A const conditional loop requires a compile-time false condition.

Moth Markdown

$md supports headings, paragraphs, lists, emphasis, links and same-line paired single-backtick code. It escapes raw HTML and has no fenced code blocks or pipe tables. Use $code for blocks and helpers for tables. Static headings render generated kebab-case IDs, so @#my-section (My section) and @/route#my-section (My section) link to them.

Links use @./path (label), @/site-route (label) or @https://example.com (label). A single leading / uses origin. Other targets render literally. Link targets neither resolve files nor create resource dependencies.

Separate target and label with a non-empty gap containing only spaces, tabs and at most one line break (LF, CRLF or lone CR). Other content or a second break prevents association. Links cannot cross inline blocks, opaque expressions or child-template boundaries.

See Templates.

Wiring

Wire and Route describe parameter capabilities through the following contracts. They are not general wrapper types.

Wires

read_name |value Wire of String| -> String:
    return value
;

forward_name |value Wire of String| -> String:
    return read_name(value)
;

name ~= "Priya"
label = forward_name(name)

Wire of T accepts a named mutable/immutable local or compatible wire parameter, preserving identity across reassignment without markers. An ordinary T receiver reads the current value under normal alias/copy rules. Wires grant no mutation and reject field projections, lookups, literals, calls and computations.

Routes

TodoMessage ::
    Rename | id Int, value String |,
    Delete | id Int |,
;

todo_id = 42

A route parameter accepts only a direct choice constructor or an unchanged compatible route parameter:

Parameter contract

Constructor argument

on_input Route of String -> TodoMessage

TodoMessage::Rename(todo_id)

on_click Route of TodoMessage

TodoMessage::Delete(todo_id)

Route of Message takes no future input, while Route of Input -> Message takes one. Contracts match input/output types exactly. Captures evaluate when the route forms and fill a leading payload prefix. Future input fills the remaining trailing payload in declaration order. Route parameters forward unchanged to compatible parameters. Elsewhere, constructors require complete arguments.

These contracts annotate parameters only, never locals, fields, choice payloads, collections/maps, aliases, defaults or return slots. Normal access and lifetime rules apply. Routes cannot be invoked, composed, compared, serialised or sent through channels. Wiring adds no automatic observation, template updates or event delivery.

See Wiring contract.

Dependencies and aliases

Bind declarations with @path, without an import keyword:

@core/math sin, cos, PI
@components render as render_component, Button as UiButton
@core/text as text
@vendor/drawing.js as drawing

Selections bind file-local names. Entry as renames one selection. Clause as names a namespace and forbids selections. Bindings span the file and cannot shadow names.

The path and first selection share a physical line. Commas continue lists and require another selection:

@core/math sin,
    cos

Bare @core/math binds math. Source namespaces allow shallow access such as math.sin(1.0), not passing as values. External package namespaces may nest. Explicit-extension dependencies such as .js require as or a direct selection.

  • Resolve from the owning module root.
  • Omit .moth, .mtf and .md extensions, but keep provider extensions such as .js.
  • Bind same-module files, module directories or registered packages, never @*.moth, +*.moth or config.moth files.
  • Reject @./, @/, parent traversal and @@.
  • Stop at child-module/support-package boundaries and use exports.
  • Select flat names after the path, never @core/math/sin.

Clauses bind available files/packages without acquiring packages. Only direct external dependencies are source-visible. See Packages and dependencies.

File values and resources

Explicit-extension file expressions produce String, without a Path type:

logo #= @assets/logo.svg
image #= [$html:<img src="[logo]" alt="Moth">]

.mtf/.md give content strings. .moth has no file value. Other accepted extensions give resource strings with ordinary storage, parameter, return and export rules.

Paths follow module-root resolution and child-module/support-package boundaries. Share resources across boundaries through exported Strings or function results. Physical paths must name existing regular files. @./, parent traversal, @@, absolute paths such as @/logo.svg and file values in config.moth are invalid.

Resource URLs depend on their output. Constants can hold resources, but compile-time operations cannot inspect unresolved URL characters. Physical references must resolve even in unused constants or inactive branches. Only resources used by output are emitted.

Bare @/ gives origin or / by default, names no file and remains invalid in dependencies. External/protocol-relative URLs stay literal and untracked.

See File paths and resource values.

Modules, exports and packages

One directory-scoped @*.moth roots a normal module. The suffix carries no meaning. Ordinary .moth files and unrooted subdirectories belong to that module.

Module files can bind helper-file declarations. Other modules see only the root's export: block:

private_label #= "Moth"

export:
    greeting #= "Hello"

    render || -> String:
        return [: [greeting], [private_label]]
    ;

    @core/math PI
;

A root allows one non-empty export:. Export functions, structs, choices, aliases, traits, constants or direct dependency selections, never runtime bindings, fragments, statements or whole namespaces. Public signatures cannot expose private types, traits or required evidence. Receiver types expose their methods, while aliases alone do not expose private implementation methods.

A source-tree +*.moth creates a directory-named support package: src/shared/+package.moth gives @shared. It uses export: and forbids top-level runtime work/pages. Support packages share code between normal siblings, which cannot depend directly on one another.

A support package serves its nearest normal owner, normal siblings and their descendants, excluding its private implementation subtree and same-scope support packages. Consumers cannot traverse its public boundary into implementation files.

One optional project-root +*.moth beside config.moth exposes the external API. Internal modules cannot bind this facade. It has no page/runtime entry, and neither its public API nor reachable implementations may depend on private @project values.

See Project structure and Package visibility.

Directives and project configuration

$name(arguments) invokes a registered directive with compile-time positional/named arguments. With no arguments, write bare $html_builder or $page, never empty (). Unknown, unavailable or misplaced directives cause errors. Source cannot define, alias, import or override semantic directives.

Project-root config.moth contains compile-time helpers and directives, without dependencies, functions, runtime work or file values:

$config
version #String = "0.1.0"

$project(name = "my_site", version = version)
$html_builder

Use exactly one $project and, for HTML directory projects, one $html_builder. Required project fields: name and version Strings. Defaults: entry_root = "src", author = none, license = none. entry_root names a relative directory below the project root. Only predefined fields are valid. name, entry_root and template_const_loop_iteration_limit cannot depend on inputs, even through helpers.

$html_builder configures HTML output, not builder/target selection. Defaults include dev_output = "dev", release_output = "release" and origin = "/". See Project configuration.

Build inputs

$config attaches to one following explicitly typed top-level # declaration across whitespace/comments, never another item or block boundary. Dangling/duplicate markers cause errors.

$config
api_url #String

$config
analytics #Bool = false

$config
label #String?

Initialisers provide fallbacks. Without one, non-optional inputs are required and optional inputs resolve to none. Input types are String, Int, Float, Bool, Char and one optional layer. This Int-only scope is intentional: there is no Uint, Dec or fixed-width input, even though those types accept ordinary literals elsewhere. Inferred #=, local, parameter, field and mutable declarations cannot declare inputs.

Config-file fallbacks may use earlier permitted helpers. Module-source fallbacks accept primitive literals or none. Matching input names within a project/package must agree on type, optionality, required/default state and default value. Ordinary constants and $project fields neither declare nor satisfy inputs. Dependencies own separate input namespaces.

Repeat --input name=value for multiple inputs. Names use lower_snake_case. Parsing splits at the first =, preserving later equals signs. Values infer Bool, signed Int, Float, quoted Char or quoted String, in order. Other text, including bare none, becomes String. Quote-starting values require complete valid literals:

moth build . --input api_url=https://example.com --input analytics=true
moth build . --input 'label="true"'
moth build . --input "separator=':'"

Types must match exactly, except present T satisfies T?.

Read predefined project fields explicitly:

@project version
footer #= [: Version [version]]

@project cannot be directly re-exported. Helpers/inputs do not become project fields.

See Build inputs and Directives.

Pages and top-level work

Declare $page once on a normal module root or explicitly selected single-file root:

$page(title = "Moth")

#[$md:
    # Welcome
]

name = "Moth"
[: Hello, [name].]

Arguments, in order: title, description, lang, favicon, body_style, head. Each takes compile-time String?, defaulting to none for no override. head inserts HTML and metadata accepts resource strings. Same-file references must name earlier constants.

$page applies to the whole root, supplying the purpose required for runtime bindings, calls and direct output. Declaration-only roots and documentation/comment templates need no purpose. Helpers, support roots, facades, config.moth and export: cannot declare pages.

Entry work runs once at startup. Dependencies neither run it nor insert fragments. Built-in Error! permits compatible top-level !. Custom errors require recovery.

Direct const fragments fold into static HTML. Plain fragments run at startup and publish only on success, with static/runtime output in source order. Failure preserves static fragments, publishes no runtime fragments and does not roll back earlier side effects. Release pages show a generic safe notice, never the application's Error message as HTML.

Directories determine routes: src/guide/@page.moth produces guide/index.html, independent of root filename. index.moth has no special role. check accepts declaration-only/zero-page projects but rejects unpurposed runtime work. HTML build/dev require a page below entry_root, without a mandatory homepage. Single-file HTML needs $page.

See Pages, metadata and entry behaviour.

Commands and project builders

moth new html my-site
cd my-site
moth check .
moth dev .
moth build . --release

check validates the project and required target capabilities without writing output. dev serves the development build. build --release writes configured release output.

Modular project builders supply packages, capabilities and output conventions. HTML turns page roots into documents/routes. Other builders provide their own source/host packages. Source cannot query/select OS, architecture, backend or physical target. The selected target must support every reachable required capability.

Core IO and foreign functions

The prelude exposes io as @core/io. io.print, io.line, io.debug, io.warn and io.error each take one String and return nothing. io.line adds a newline. Format other values with templates:

count = 3
io.line([: Count: [count]])

io.set_title(text) takes one String, returns nothing, declares no error channel and requires browser document-title capability. It sets the exact live title without initial prefix/postfix, leaving static metadata and routes unchanged.

Annotated JavaScript files expose typed free functions:

/**
 * @moth.sig emphasize |text String| -> String
 */
export function emphasize(text) {
    return `**${text}**`;
}
@vendor/format.js emphasize

label |text String| -> String:
    return emphasize(text)
;

Annotations name Moth functions independently of JS exports. Signatures use positional typed parameters and either zero/one success result with an optional final Error!, or the whole -> ! contract. Numeric signatures accept Int, Uint and Float alongside the other supported types: Uint32 crosses as a Number integer, while Uint64 crosses as a BigInt inside Moth JavaScript and through the safe-Number foreign bridge only. Declare opaque types with @moth.opaque before use. This surface rejects JS constants, receiver methods, callbacks, async, options, collections, generics and multiple success results.

Foreign code cannot retain Moth-storage references. Opaque handles represent foreign identities with declared resource lifecycles. WIT provides a value-only foreign Wasm boundary, separate from native Moth imports.

See Core IO and Foreign binding contracts.
